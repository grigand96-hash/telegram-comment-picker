# Как устроена защита

GitHub Pages отдаёт HTML, CSS и JavaScript. Страница обращается к приложению на `127.0.0.1:8894`, а оно получает комментарии через Telegram API. API hash и ключ Telegram-сессии остаются на компьютере. В коде интерфейса нет сторонних скриптов, аналитики или внешних шрифтов.

Приложение слушает только локальный адрес. Оно проверяет Host и Origin, ограничивает размер POST-запросов и принимает их только в JSON. Страница на GitHub Pages может проверить подключение, запустить выбор и получить прогресс. Вход в Telegram доступен только с локальной страницы. Ошибки проверки полей не возвращают введённые значения.

Приватный каталог имеет права `0700`, файлы с ключами `0600`. Они находятся вне репозитория и не раздаются веб-сервером. Telegram-сессия не сохраняет новые записи о контактах через механизм кеширования Telethon. Текст комментариев выводится через `textContent`, поэтому HTML из комментария не исполняется. Политика CSP ограничивает источники скриптов и сетевых запросов.

## Случайный выбор

Приложение полностью загружает доступную ветку обсуждения и передаёт список обычных сообщений в `secrets.choice`. Сервисные сообщения исключаются. У каждого комментария один шанс, в том числе у нескольких комментариев одного автора. При ошибке загрузки неполный список не используется.

`secrets` использует источник случайности операционной системы: [документация Python](https://docs.python.org/3/library/secrets.html). В приложении нет списка предпочтительных авторов или заданного победителя. Повторный выбор разрешён и может вернуть тот же комментарий.

## Проверка 12 ноября 2026 года

- Проверена история Git в локальных и удалённых ветках: совпадений с используемым API hash и ключом сессии в двоичном, hex- и base64-виде не найдено. Дополнительный поиск распространённых форматов токенов также не дал совпадений.
- Публичная ветка `gh-pages` содержит только три файла интерфейса. В репозитории не настроены GitHub Actions secrets.
- Зависимости обновлены и закреплены в `requirements.txt`. Проверка `pip-audit` после обновления не нашла известных уязвимостей.
- Автоматические проверки покрывают запрет посторонних Origin и Host, доступ к закрытым файлам, размер и формат запросов, скрытие секретов в ошибках, полную загрузку ветки, выбор комментария, прогресс и повторную загрузку после обновления страницы.
- Все 13 автоматических тестов прошли. Дополнительно выполнены три пробных выбора на настоящей ветке ZNWR из 1 000 комментариев. Отдельное чтение ветки через Telegram подтвердило количество сообщений, ссылки и тексты всех трёх результатов. Эти результаты не объявлялись победителями конкурса.
- Во время проверки процесс слушал только `127.0.0.1:8894`; единственное наблюдаемое исходящее TCP-соединение процесса было с Telegram.

Повторить автоматические проверки можно в изолированном окружении из README:

```sh
python -m unittest -q test_app
uvx pip-audit --no-deps --disable-pip -r requirements.txt
```

Тесты используют временный каталог и подставные данные, не входят в реальный аккаунт и не выбирают победителя конкурса.

## Границы защиты

Telegram-сессия даёт доступ к аккаунту, хотя приложение использует его только для чтения обсуждения и авторизации. Доступ к файлу сессии со стороны другого приложения или человека опасен. Это свойство Telegram-сессий описано в [документации Telethon](https://docs.telethon.dev/en/stable/concepts/sessions.html).

Проверка Origin защищает от обращений с посторонних сайтов, но не является авторизацией для программ на самом компьютере. Доверенными остаются компьютер, его пользователь, зависимости, GitHub-аккаунт и весь источник `https://grigand96-hash.github.io`: браузер не разделяет Origin по путям отдельных репозиториев. Проверка не включает аудит других сайтов этого владельца, расширений браузера или всей системы.

Открытый код позволяет проверить алгоритм и самостоятельно его запустить. Он не доказывает, что организатор запускал именно этот код или не повторял выбор. Неизменяемого журнала результатов здесь нет.

Проверка репозитория и текущих соединений не доказывает отсутствие любой утечки в прошлом. Отсутствие известных уязвимостей на дату проверки также не гарантирует, что новых уязвимостей не появится.
